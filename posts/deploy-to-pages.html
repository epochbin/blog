Putting It on GitHub Pages

2026 年 11 月 2 日Nov 2, 2026阅读约 2 分钟About 4 min read

从零到能访问，大概十分钟。一共四步。

一、建仓库

打开 github.com，右上角 + → New repository。

  • 名字随意，比如 blog
  • 选 Public（私有仓库的 Pages 要付费，评论也用不了）
  • 不用勾 README，空的就行

建好后仓库地址类似 github.com/你的用户名/blog

二、拿一个 Token

这是唯一有点门槛的一步。

打开 https://github.com/settings/personal-access-tokens/new

  • Token name：随便，比如 blog-publisher
  • Expiration：可以选 No expiration，省得半年后过期
  • Repository access：选 Only select repositories，只勾刚才那个 blog
  • Permissions → 找到 Contents，改成 Read and write

其他权限一个都不用给。

生成后那串字符只显示一次，先复制到备忘录。

三、填进编辑器

打开这个 HTML，点底栏 设置：

  • GitHub 用户名
  • 仓库名（blog）
  • 分支（main）
  • Token（粘上刚才那串）
  • 站点标题、副标题、你的邮箱
  • 站点地址：https://你的用户名.github.io/blog

保存。设置面板底部有「测试连接」，点一下，能读到仓库就说明 Token 对了。

四、开 Pages 并发布

回到仓库，Settings → Pages：

  • Source 选 Deploy from a branch
  • Branch 选 main，目录选 /(root)
  • Save

然后回编辑器，点底栏 发布。等几十秒，访问：

https://你的用户名.github.io/blog/

第一次可能要等一两分钟，刷新几次。

之后每次

写完 → 点发布 → 等半分钟。没有别的事要做。

几个坑

  • Token 只读会导致 404。填的时候确认 Contents 是 Read and write，不是 Read
  • 仓库如果是 用户名.github.io，站点地址就是 https://用户名.github.io/，没有子路径
  • 发布失败先看面板里的日志，它会写清楚卡在哪一步（读分支、建树、提交、更新分支）
  • 想清空重来，用设置里的「清空仓库」，它会二次确认

From nothing to a live site in about ten minutes. Four steps.

1. Create a repository

Go to github.com, click + → New repository.

  • Any name, say blog
  • Choose Public (Pages on private repos is a paid feature, and comments won't work either)
  • Leave it empty — no README needed

The URL will look like github.com/yourname/blog

2. Get a token

This is the only fiddly part.

Open https://github.com/settings/personal-access-tokens/new

  • Token name: anything, e.g. blog-publisher
  • Expiration: No expiration is fine, saves you a renewal
  • Repository access: Only select repositories → just the blog repo
  • Permissions → find Contents → set it to Read and write

Nothing else needs permission.

The token is shown once. Copy it somewhere safe.

3. Fill in the editor

Open the HTML file and tap 设置 (Settings) in the bottom bar:

  • GitHub username
  • Repository name
  • Branch (main)
  • Token
  • Site title, tagline, your email
  • Site URL: https://yourname.github.io/blog

Save. At the bottom of the panel there's "测试连接" — tap it; if it can read the repo, the token is right.

4. Enable Pages and publish

Back in the repo: Settings → Pages

  • Source: Deploy from a branch
  • Branch: main, folder /(root)
  • Save

Then hit 发布 (Publish) in the editor. Wait a bit, then open:

https://yourname.github.io/blog/

The first deploy can take a minute or two — refresh a couple of times.

After that

Write → publish → wait half a minute. That's the whole loop.

Common traps

  • A read-only token produces 404s. Make sure Contents is Read and write
  • If the repo is yourname.github.io, the URL is https://yourname.github.io/ with no subpath
  • If publishing fails, read the log in the panel — it tells you which step broke
  • To start over, use "清空仓库" in settings; it asks for confirmation
