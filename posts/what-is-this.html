这个博客是怎么回事

What This Blog Actually Is

2026 年 11 月 3 日Nov 3, 2026阅读约 2 分钟About 4 min read

你现在看到的这个站点，是用一个 HTML 文件生成的。

那个文件既是编辑器，也是生成器：打开它写文章，点发布，它把整站重新生成一遍，直接推到 GitHub。GitHub Pages 负责把它变成你能访问的网页。

没有服务器，没有数据库，没有构建流程，也没有 npm install。

它到底怎么跑起来的

三条链：

写：文章内容存在浏览器的 localStorage 里。关掉页面不丢，清空浏览器数据才会丢。

生成：点发布的时候，所有文章被拼成静态 HTML（首页、归档、标签页、每篇文章、RSS、搜索索引），同时算一遍每个文件的哈希，只上传变化的。

上线：生成好的文件通过 GitHub API 提交到你的仓库，Pages 自动重新部署，几十秒后新内容就出现在网址上。

你的浏览器  ──生成──▶  静态文件  ──API──▶  GitHub 仓库  ──▶  Pages
   (编辑器)                                  (版本历史)

能做什么

  • Markdown 写正文，支持代码块、表格、图片、内联 HTML
  • 中英双语：每篇文章可以写两份，报头自动出「中 / EN」
  • 标签：文章只选标签，名字和英文名在标签管理器里统一维护
  • 独立页面：关于我、友链这类，可以不放进导航
  • RSS / 搜索 / 明暗切换 / 阅读进度，都是自动的
  • 图片：在编辑器里选图，自动压缩，发布时一起推到仓库
  • 评论：接 giscus，用 GitHub Discussions 存，可开可关

它的局限，先说清楚

  • 数据在浏览器里。换手机、换浏览器、清了缓存，都得先导出备份再用
  • 一个文件就是一个站。把 HTML 挪到别的路径，等于换了一个没有数据的空站
  • 没有后台。所有事情都在你这台设备的浏览器里发生，包括发布

接受这三条，它就是一个非常省心的写作工具。不接受，它确实不适合你。

接下来看哪篇

  • 想部署到自己的 GitHub → 《把它挂到 GitHub Pages》
  • 想让人留言 → 《打开评论区》

这两篇会一步一步写。

The site you're reading was generated by a single HTML file.

That file is both the editor and the generator: open it, write, hit publish, and it rebuilds the whole site and pushes it to GitHub. GitHub Pages turns it into the pages you're looking at.

No server, no database, no build pipeline, no npm install.

How it works

Three links in the chain:

Write — posts live in the browser's localStorage. Closing the tab is fine; clearing browser data is not.

Build — on publish, everything is rendered to static HTML (home, archive, tag pages, each post, RSS, search index), and each file is hashed so only changed ones are uploaded.

Ship — the generated files are committed through the GitHub API; Pages redeploys and the new content appears in under a minute.

your browser  ──render──▶  static files  ──API──▶  GitHub repo  ──▶  Pages
  (editor)                                          (version history)

What it does

  • Markdown with code blocks, tables, images, inline HTML
  • Bilingual: write both versions, the header grows a 中 / EN switch
  • Tags: posts pick tags, names live in the tag manager
  • Standalone pages: about, links — optionally out of the nav
  • RSS, search, dark mode, reading progress — all automatic
  • Images: pick one in the editor, it's compressed and uploaded on publish
  • Comments: giscus, backed by GitHub Discussions, switchable

The honest limitations

  • Your data lives in the browser. New phone, new browser, cleared cache — export a backup first
  • One file is one site. Move the HTML elsewhere and you get an empty site with no data
  • No backend. Everything happens in your browser, including publishing

If those three are acceptable, it's a very low-maintenance writing tool. If not, it genuinely isn't for you.
