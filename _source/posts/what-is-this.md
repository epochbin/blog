你现在看到的这个站点，是用一个 HTML 文件生成的。

那个文件既是编辑器，也是生成器：打开它写文章，点发布，它把整站重新生成一遍，直接推到 GitHub。GitHub Pages 负责把它变成你能访问的网页。

没有服务器，没有数据库，没有构建流程，也没有 npm install。

## 它到底怎么跑起来的

三条链：

**写**：文章内容存在浏览器的 localStorage 里。关掉页面不丢，清空浏览器数据才会丢。

**生成**：点发布的时候，所有文章被拼成静态 HTML（首页、归档、标签页、每篇文章、RSS、搜索索引），同时算一遍每个文件的哈希，只上传变化的。

**上线**：生成好的文件通过 GitHub API 提交到你的仓库，Pages 自动重新部署，几十秒后新内容就出现在网址上。

~~~
你的浏览器  ──生成──▶  静态文件  ──API──▶  GitHub 仓库  ──▶  Pages
   (编辑器)                                  (版本历史)
~~~

## 能做什么

- **Markdown 写正文**，支持代码块、表格、图片、内联 HTML
- **中英双语**：每篇文章可以写两份，报头自动出「中 / EN」
- **标签**：文章只选标签，名字和英文名在标签管理器里统一维护
- **独立页面**：关于我、友链这类，可以不放进导航
- **RSS / 搜索 / 明暗切换 / 阅读进度**，都是自动的
- **图片**：在编辑器里选图，自动压缩，发布时一起推到仓库
- **评论**：接 giscus，用 GitHub Discussions 存，可开可关

## 它的局限，先说清楚

- **数据在浏览器里**。换手机、换浏览器、清了缓存，都得先导出备份再用
- **一个文件就是一个站**。把 HTML 挪到别的路径，等于换了一个没有数据的空站
- **没有后台**。所有事情都在你这台设备的浏览器里发生，包括发布

接受这三条，它就是一个非常省心的写作工具。不接受，它确实不适合你。
